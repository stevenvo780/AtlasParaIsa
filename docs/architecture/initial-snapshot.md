# Initial Snapshot — Wire Format

Version: protocol v1 / schema v1
Generated by: `services/realtime/src/world.ts` → `bootstrapWorld` → `worldToSnapshot`

## When does the client receive this?

Immediately upon WebSocket connection to `ws://<host>:8080/ws`.
Also re-broadcast every 1500 ticks (~30 s) after a snapshot is persisted to disk.

The client must reset its local render state on every received `SnapshotMessage`.

---

## SnapshotMessage envelope

```json
{
  "type": "snapshot",
  "protocolVersion": 1,
  "tick": 0,
  "simulatedMs": 0,
  "world": { ... }
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | `"snapshot"` | yes | Discriminant — always `"snapshot"`. |
| `protocolVersion` | `number` | yes | Must match `PROTOCOL_VERSION` in `types.ts`. Client should disconnect and show an "update required" message if it does not match its own expected version. |
| `tick` | `number` | yes | Logical tick counter. 0 for a fresh world. |
| `simulatedMs` | `number` | yes | `tick * 20`. Useful for UI clocks. |
| `world` | `Snapshot` | yes | Full world payload — see below. |

---

## `world` — Snapshot object

Produced by `@carta/sim-core`'s `snapshot(world)` function.

```json
{
  "schemaVersion": 1,
  "tick": 0,
  "simulatedMs": 0,
  "entities": [ ... ],
  "recentEvents": []
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `schemaVersion` | `1` | yes | Snapshot schema version. Increment on breaking changes to `EntitySnapshot`. |
| `tick` | `number` | yes | Same as envelope `tick`. |
| `simulatedMs` | `number` | yes | Same as envelope `simulatedMs`. |
| `entities` | `EntitySnapshot[]` | yes | All entities in the world. On fresh boot: 2 entries (S and I). |
| `recentEvents` | `unknown[]` | yes | Last ≤100 `SimEvent` objects. Empty on fresh boot. |

---

## `EntitySnapshot` — per entity

All entities in `entities` have this shape:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `string` | yes | Stable entity identifier. `"s"` or `"i"` for the two protagonists. |
| `name` | `string` | yes | Display name. `"S"` or `"I"` — single letters only; real names are not exposed. |
| `tags` | `string[]` | yes | Entity tags. Protagonists carry `["protagonist", "circle"]` or `["protagonist", "square"]`. |
| `alive` | `boolean` | yes | `true` until lifecycle system declares death. |
| `causeOfDeath` | `string` | **optional** | Only present when `alive === false`. One of `"DisconnectionDeath"` or `"EnergyDepletion"`. |
| `x` | `number \| null` | yes | World-space X position (metres). `null` if entity has no Position component. |
| `y` | `number \| null` | yes | World-space Y position (metres). `null` if entity has no Position component. |
| `energy` | `number \| null` | yes | Normalised energy `[0, 1]`. `null` if no Homeostasis component. |
| `bond` | `number \| null` | yes | Coupling strength `[0, 1]`. `null` if no Homeostasis component. THE variable for Pilar 1 (death by disconnection). |
| `mood` | `number \| null` | yes | Affective valence `[-1, 1]`. Positive = content. `null` if no Homeostasis component. |
| `heartRate` | `number \| null` | yes | Simulated BPM `[40, 180]`. `null` if no Homeostasis component. |
| `ticksBelowBondThreshold` | `number` | yes | Consecutive ticks bond has been below the lethal threshold. 0 when healthy. |
| `appearance` | `EntityAppearance` | **optional** | Rendering hint. Present when the entity has a `Renderable` component. See below. |

### `EntityAppearance` — rendering hint

Only present when the entity has a `Renderable` ECS component.
The simulation ignores this entirely; it is purely for the frontend-renderer.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `shape` | `"circle" \| "square" \| "triangle"` | yes | Phaser primitive to draw. S = circle (●), I = square (■). |
| `label` | `string` | **optional** | Short display label (1–2 chars). Not a real name — preserves the metaphor from `duo-eterno`. |
| `scale` | `number` | **optional** | Scale multiplier relative to the default sprite size. If absent, default to `1.0`. |

**Renderer contract (coordinate with `frontend-renderer`):**
- Read `appearance.shape` to decide the Phaser geometry.
- Read `appearance.label` for the display glyph, not the entity name.
- Colour, sprite, animation are renderer decisions — they do NOT live in this field.

## Real example — fresh boot (tick 0)

This is the verbatim JSON sent by `bootstrapWorld` on first connection when
`STATE_DIR` is empty (captured by running the exact pipeline used by the server):

```json
{
  "type": "snapshot",
  "protocolVersion": 1,
  "tick": 0,
  "simulatedMs": 0,
  "world": {
    "schemaVersion": 1,
    "tick": 0,
    "simulatedMs": 0,
    "entities": [
      {
        "id": "s",
        "name": "S",
        "tags": [
          "protagonist",
          "circle"
        ],
        "alive": true,
        "x": 400,
        "y": 600,
        "energy": 0.8,
        "bond": 0.6,
        "mood": 0.5,
        "heartRate": 72,
        "ticksBelowBondThreshold": 0,
        "appearance": {
          "shape": "circle",
          "label": "S"
        }
      },
      {
        "id": "i",
        "name": "I",
        "tags": [
          "protagonist",
          "square"
        ],
        "alive": true,
        "x": 600,
        "y": 600,
        "energy": 0.8,
        "bond": 0.6,
        "mood": 0.5,
        "heartRate": 72,
        "ticksBelowBondThreshold": 0,
        "appearance": {
          "shape": "square",
          "label": "I"
        }
      }
    ],
    "recentEvents": []
  }
}
```

### Coordinate system

- World is 1000 × 1000 world units (metres) — see `DEFAULT_CONFIG.space`.
- Cell size: 50 world units (matches `defaultInteractionRadius`).
- S is at grid cell (8, 12) → world position (400, 600).
- I is at grid cell (12, 12) → world position (600, 600).
- Distance between S and I at boot: 200 world units (4 cells).
- The `defaultInteractionRadius` is 50 units, so at boot they are NOT in interaction range — bond will decay until they move together.

## Subsequent snapshots (running world)

At tick N > 0 the snapshot shape is identical but fields reflect current simulation state:
- `tick` and `simulatedMs` are non-zero.
- `bond`, `energy`, `mood`, `heartRate` reflect accumulated simulation.
- `alive` may be `false` for dead entities; `causeOfDeath` will be set.
- `recentEvents` contains up to 100 `SimEvent` objects.
- `ticksBelowBondThreshold` may be non-zero if bond has been critically low.
